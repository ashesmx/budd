# ADR 0008: The local-mode UI

- Status: accepted
- Date: 2026-10-16

Phase 3 builds the UI from spec §15 for local mode. Hosted mode (ADR 0009)
reuses it, adding sign-in. Since ADR 0010, local mode has a username and
password too.

> **Correction (Phase 4):** this ADR first specified `Referrer-Policy:
no-referrer`. Under that policy browsers send `Origin: null` on form POSTs,
> so the origin check refused every UI form in real browsers. It is now
> `same-origin`; see ADR 0009.

## Rendering

- **Pages are rendered on the server** with Hono's `html` tagged template, which
  escapes every interpolated value. There's no JSX, build step or client
  framework. Message bodies, payloads, labels and subjects are shown as escaped
  text, never rendered as markdown.
- **CSS and JS are served as files** (`/ui/app.css`, `/ui/app.js`), so the
  Content-Security-Policy can forbid inline script and style:
  `default-src 'none'; script-src 'self'; … frame-ancestors 'none'`.
  `X-Frame-Options: DENY` is sent too. The confirm dialog must never be
  clickjackable.
- **Light and dark mode** follow the OS (`prefers-color-scheme`).
- `GET /` redirects to `/ui`. The startup banner prints the UI URL.

## Live updates

- **Every audit write publishes an event** on the `EventBus` for its workspace.
  Every state change is audited (ADR 0007), so the UI sees exactly what the
  audit log sees, and no publish calls are scattered through the code.
- `GET /ui/events` is an SSE stream of `change` pings carrying only the event
  kind (e.g. `send`), never content.
- Pages marked live (connections, messages, audit) fetch themselves again and
  swap in the new `<main>`. They wait while the human is typing in a field. The
  policy page isn't live, so a half-made choice is never replaced.

## Sessions and CSRF

- A **session cookie** (`budd_session`): `HttpOnly`, `SameSite=Strict`, and
  `Secure` over HTTPS. It starts at sign-in in hosted mode, and at `/login` or
  `/setup` in local mode (ADR 0010). Sessions live in memory, so a restart
  means signing in again, and end after 12 hours unused or 7 days after
  sign-in.
- **Every POST needs** the session cookie, that session's CSRF token, and, if
  the browser sends an `Origin`, the UI's exact origin. `SameSite` alone isn't
  enough here: a page on another local port (`localhost:3000`) counts as
  same-site. The Host/Origin guard from Phase 1 also covers every UI request.

## Policy changes (§9)

- **Narrowing applies in one step.** Agents can narrow too, so a confirmation
  would add nothing.
- **Widening takes two requests.** The first only records the proposed change
  and returns a confirm dialog carrying a one-time nonce. The nonce is:
  - bound to the browser session and to that connection;
  - valid for 5 minutes;
  - usable once.

  The second request presents the nonce. Budd then checks that the policy
  hasn't changed since the dialog was shown, and applies exactly the change the
  human saw. No single request can widen a policy. Beneath this, the `Admin`
  service refuses any widening that isn't marked as confirmed (ADR 0007 §11).

- Each dialog names the connections that would be let in, or says "every
  connection in this workspace".

## Other admin actions

- **Block and relabel apply in one step.**
- **Unblock is confirmed** with the same nonce-bound dialog as widening, since
  it lets a connection back in. The maintainer asked for this after Phase 3.
  The `Admin` service refuses an unconfirmed unblock too.
- A nonce confirms only the kind of change it was issued for.

## What the UI shows

- **Live queues:** unread count per mailbox (`connection/handle`).
- **Connections:** status, last seen, label, and who may message each one.
- **Messages:** history within retention, newest first, with each recipient's
  delivery state (`unread`, `read` or `expired`). Bodies and payloads are shown:
  the local human owns the workspace.
- **Audit log:** newest first, metadata only.
- Every handle is rendered by one helper, which always adds an "unverified" tag.
  A test checks that no handle appears without it.
